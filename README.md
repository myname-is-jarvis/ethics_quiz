# 행사 퀴즈 설치 순서

구성: `index.html`(정적 페이지, 아무 HTTPS 호스팅) + `Code.gs`(Google Apps Script, 문제·결과는 Google Sheet에 저장)

흐름: QR → index.html → 이름·전화·동의 입력 → Apps Script가 시트에서 10문제 랜덤 추출(보기도 셔플) → 답 제출 → 서버 채점 후 Results 시트에 저장 → 점수와 정답 표시

## 설치

1. Google Sheet를 새로 만들고 `확장 프로그램 > Apps Script`를 엽니다. 기본 코드를 지우고 `Code.gs` 내용을 붙여넣고 저장합니다.
2. 함수 선택에서 `setupSheets`를 실행하고 권한을 승인합니다. `Questions`, `Results` 시트가 생깁니다.
3. `Questions` 시트에 문제를 입력합니다.
   - `id`는 유일해야 합니다 (중복되면 채점이 꼬입니다).
   - 한 문제 안에서 보기 텍스트가 서로 달라야 합니다 (텍스트로 채점).
   - `answer`는 정답 보기 번호(1~4), 보기는 2~4개.
   - `active`에 `N`을 넣으면 출제에서 빠집니다. 재배포 없이 즉시 반영됩니다.
   - "위의 모두", "①과 ③" 같은 순서 의존 보기는 쓰지 마세요 (보기가 셔플됩니다).
4. `testQuestions`를 실행해 실행 로그에 10문제 JSON이 찍히는지 확인합니다.
5. `배포 > 새 배포` → 유형 **웹 앱** / 실행 사용자 **나** / 액세스 권한 **모든 사용자** → 배포 → 웹 앱 URL 복사.
6. `index.html`의 `API_URL`을 그 URL로 바꾸고, `EVENT_TITLE`과 개인정보 고지 문구(`[확인 필요]`)를 수정합니다.
7. `index.html`을 GitHub Pages, Netlify, Cloudflare Pages 등 HTTPS 호스팅에 올리고, 그 주소로 QR을 만듭니다.
8. 실제 휴대폰으로 처음부터 끝까지 한 번 진행해 `Results`에 행이 추가되는지 확인한 뒤 테스트 행을 지웁니다.

## 통계

Apps Script 편집기에서 `buildStats`를 실행하면 `Stats` 시트가 만들어지거나 갱신됩니다.
참여자 수, 평균 점수, 점수 분포(0~10), 문제별 출제 횟수·정답률, 순위(동점이면 먼저 제출한 사람이 위)가 들어갑니다. 행사 중에도 반복 실행할 수 있습니다.

## 주의

- `Code.gs`를 고친 뒤에는 `배포 관리 > 새 버전`으로 다시 배포해야 반영됩니다.
- `Results` 시트를 직접 만들었다면 C열(phone)을 `서식 > 숫자 > 일반 텍스트`로 두세요. 그렇지 않으면 앞자리 0이 사라질 수 있습니다.
- 중복 참여는 전화번호 기준으로 막습니다. 허용하려면 `CONFIG.ALLOW_DUPLICATE_PHONE = true`.
- 정답은 제출 전에 브라우저로 내려가지 않고 서버에서만 채점합니다.
- 이름·전화번호를 수집하므로 개인정보 수집·이용 동의 문구(항목, 목적, 보유기간, 거부권)는 담당자 확인이 필요합니다.

## 실제 배포 환경에서 검증하지 못한 부분

- Apps Script 웹앱의 동시 실행 한도 수치. 참여가 행사 중 분산된다면 문제 될 가능성은 낮다고 판단하지만, 확인된 수치는 아닙니다.
- 브라우저 `fetch` → Apps Script `POST`(`text/plain` 전송, 리다이렉트 후 응답 읽기)는 널리 쓰이는 패턴이지만, 반드시 실제 휴대폰에서 8번 항목대로 테스트하세요.
- 백엔드 로직(랜덤 추출, 비활성 제외, 채점, 중복 차단, 통계)은 Apps Script 서비스를 흉내 낸 로컬 테스트로만 확인했습니다.
